# Myanmar Tipitaka V2.3.4.8.8 — Reader Reliability & Backup/Restore

## Version
- Android versionName: 2.3.4.8.8
- Android versionCode: 31
- Base branch: v2.3.4-offline-reader-critical-fix

## Implemented in this increment
1. Added native `ReaderStateBackupActivity`.
2. Registered the activity in AndroidManifest.
3. Added an entry from Page 12 (Bookmarks & Notes) to Reader Backup / Restore.
4. Backup uses Android Storage Access Framework (Create Document); no broad storage permission is requested.
5. Restore uses Open Document, validates the JSON format and schema version, and restores only an explicit allowlist of reader-state keys.
6. File size is limited to 5 MiB; import is committed atomically through SharedPreferences Editor.commit().
7. Existing reader-state keys remain compatible:
   - bookmark_<paragraph_id>
   - history_<paragraph_id>
   - note_<paragraph_id>
   - reader_font
   - last_volume, last_paragraph_id, last_read_at
   - volume_<n>_page
8. Version code/name incremented to 31 / 2.3.4.8.8.

## Backup format
- format: `myanmar-tipitaka-reader-state`
- schema_version: 1
- created_at: Unix milliseconds
- item_count: exported allowlisted entries
- values: JSON object of typed values

The restore process ignores keys outside the allowlist. It does not import SQL, executable content, Pāli scripture, or translation records. It does not erase existing reader data before applying restored values.

## Database reliability policy
- The packaged Tipiṭaka corpus remains read-only in the app.
- Do not alter the 45-book source corpus or mark a Myanmar text as approved during an app migration.
- Before any corpus schema upgrade, verify database file integrity, schema version, paragraph primary keys, segment IDs, and volume mapping; stage a copy, migrate it, run integrity and count checks, then atomically replace the installed copy.
- Keep translation and explanation as separate content types, keyed to a stable segment ID.
- Approved status requires source rights/evidence, two distinct reviewers, a review reference, and review date. AI-generated drafts must remain explicitly unapproved.
- Translation and explanation counts must be reported independently. Empty tables must never be represented as completed Myanmar coverage.

## QA checklist
- Page 12 -> Backup/Restore opens the new screen.
- Export to Downloads or Drive via Android document picker.
- Validate backup JSON format and item_count.
- Clear app data in a test install, restore backup, and verify bookmark/note/history/font/page values.
- Try invalid JSON, wrong format, unsupported schema version, oversized file and empty values; restore must reject safely.
- Verify unrelated SharedPreferences and corpus files are not modified.
- Reopen Pāli paragraph reader in airplane mode.
- Test Samsung Android device: screen rotation policy, font scaling, Myanmar Unicode display and file picker.
- Verify build artifact is uploaded only if the offline corpus verification gate passes.

## Known limitations / release blockers
- This feature backs up local reader state only; it does not back up the Tipiṭaka SQLite corpus.
- No cloud sync is implemented.
- This commit does not supply the missing/licensed 45-volume SQLite corpus.
- This commit does not add approved Myanmar translation or explanation content. A separate verified content dataset is required.
- APK must not be called release-ready until Gradle compilation succeeds, artifact upload succeeds, and the offline corpus gate passes.
