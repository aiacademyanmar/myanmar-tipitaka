# Myanmar Tipitaka V2.3.4.8.2 — Offline Reader & Content QA

## Changes in this increment
- Android package version aligned to 2.3.4.8.2 (versionCode 25).
- Page 11 no longer displays fabricated category-title matches as search results; it opens the real SQLite OfflineSearchActivity.
- OfflineSearchActivity accepts an initial query and a Tipiṭaka group filter.
- Search can match Pāli body, reviewed Myanmar translations and reviewed Myanmar explanations when the corresponding Myanmar table exists.
- Results show the actual Pāli paragraph and available reviewed Myanmar translation/explanation snippets, then open the exact paragraph in the reader.
- The search filter is retained as an Activity field so the search callback can access it safely.

## Critical repository finding
The expected asset `app/src/main/assets/tipitaka_offline.sqlite` is not present at the inspected branch path. OfflineCorpusInstaller.prepare() requires this asset to install the corpus. Therefore:
- A successful Java/Gradle compile would not prove the 45-book corpus is bundled.
- On a clean install, OfflineCorpusInstaller is expected to report that the asset is unavailable unless the database is supplied under the exact asset path.
- Do not claim 45-book offline reading or Myanmar content coverage until the actual database is included and verified.

## Myanmar content integrity
- The current reader supports the legacy `paragraph_myanmar_content` and `paragraph_explanations` structures with reviewed flags.
- The newer `TipitakaContentDatabase` is a separate normalized foundation; it is not yet migrated/populated from the legacy paragraph corpus.
- No approved Myanmar translation or explanation dataset is being fabricated in this increment.
- Content remains unapproved until a named qualified reviewer, source reference, review date and approval record are supplied.
