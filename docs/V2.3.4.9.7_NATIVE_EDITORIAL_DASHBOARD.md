# Myanmar Tipitaka V2.3.4.9.7 — Native Myanmar Editorial Coverage Dashboard

## Android version
- versionName: 2.3.4.9.7
- versionCode: 40
- Branch: v2.3.4-offline-reader-critical-fix

## Changes
1. Extended the native Myanmar coverage screen with a per-volume breakdown.
2. Each available volume displays Pali paragraph count, approved translation count/percentage, approved explanation count/percentage, and a direct button to open that volume in the offline native reader.
3. Counts are based only on rows in paragraph_myanmar_content with reviewed=1 and non-empty Myanmar text.
4. Both-content coverage joins through paragraph_id, matching the editorial importer schema.
5. Added a visible entry in the Tipitaka contents menu to open the Myanmar Translation Coverage dashboard.
6. Updated Android version metadata and GitHub workflow labels to 2.3.4.9.7 / 40.

## Important limitations
- This is an offline read-only editorial progress dashboard, not a remote multi-user admin server.
- It does not allow unreviewed content to be approved on-device.
- Content entry/import remains a controlled, rights-cleared CSV workflow, with two distinct reviewers and matching Pali SHA-256.
- No Myanmar translations or explanations are fabricated. Empty or missing content is reported as zero coverage.
- Actual MCU 45-volume mapping and a complete native SQLite corpus remain prerequisites for full book-by-book reporting and a complete APK release.

## QA
The workflow runs importer regression tests, corpus and crosswalk gates, editorial batch audit, per-volume coverage report, and Android debug compilation. APK artifact publication remains conditional on corpus and crosswalk gates.
