## Myanmar Tipitaka V2.3.4.9.9 — Editorial Review Decisions

Android version: 2.3.4.9.9 / versionCode 42
Branch: v2.3.4-offline-reader-critical-fix

### Changes
1. Added an on-device Reviewer Queue for submitted drafts.
2. Reviewers can record Approve, Revision Required, or Reject decisions with notes.
3. Review decisions are stored separately in the private editorial drafts SQLite database.
4. Reviewer names use case-insensitive uniqueness per paragraph to prevent capitalization variants counting twice.
5. State derives from decisions: any rejection -> rejected; any revision -> revision_requested; two distinct approvals -> reviewed_locally; otherwise submitted_for_review.
6. Draft retrieval is keyed by volume plus paragraph ID.
7. Android metadata and CI labels updated to 2.3.4.9.9 / 42.

### Important boundaries
- Reviewer names are self-entered, not authenticated identities; this is a local workflow aid, not proof of independent scholarly review.
- reviewed_locally is not publisher approval or publication.
- Reviewer decisions do not change the shipped offline corpus.
- No Myanmar content is invented, auto-approved or published.
- Canonical SQLite import still requires verified source, rights evidence, distinct reviewers and matching Pali SHA-256.
- Production governance requires authenticated accounts and audit logs.

### QA
GitHub workflow checks source and compiles Android. Corpus and crosswalk gates remain separate. Successful compilation does not mean Myanmar translation/explanation coverage is complete.
