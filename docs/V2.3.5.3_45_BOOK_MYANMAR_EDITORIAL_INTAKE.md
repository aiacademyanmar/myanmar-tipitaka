# Myanmar Tipitaka V2.3.5.3 — 45-Book Editorial Intake Foundation

## Release intent
Standalone Android APK only. No publisher web dashboard or server is required. The APK remains the place for local drafting, review records, direct local publish, coverage, and backup/restore.

## Verified baseline from repository records
- The current editorial workflow dossier records 425,953 source-aligned Pali paragraphs across the intended 45-volume native corpus.
- Each paragraph requires two separate editorial work units: one Myanmar translation and one Myanmar explanation (851,906 work units if every source paragraph is included).
- The checked-in corpus/reviewed_myanmar.csv contains only its header. It therefore contributes zero approved translation rows and zero approved explanation rows.
- The 38 Maṅgala Sutta Myanmar draft rows and Dhammapada draft files are marked as drafts/unreviewed. They are not counted as verified or published.
- The 45-volume crosswalk currently contains UNVERIFIED rows. Candidate source-family guesses are not exact approved printed-edition boundaries.
- Consequently this release does not claim 45-book verified Myanmar content is complete, nor does it fabricate missing translations, explanations, reviewer identities, rights permissions, or approvals.

## V2.3.5.3 implementation
1. Added scripts/build_myanmar_editorial_batches.py. It creates per-volume CSV work units only when a native SQLite corpus and fully VERIFIED 45-volume crosswalk are available. Each Pali paragraph gets separate translation and explanation rows, Pali source reference, exact SHA-256, and blank Myanmar/editorial fields.
2. Added scripts/test_myanmar_editorial_batches.py to verify that a missing corpus produces a 45-row book manifest with BLOCKED status and zero invented approved content.
3. CI now runs the batch planner tests and generates a 45-book editorial manifest and intake report, even if the native corpus is missing.
4. The standalone Publisher coverage screen now calculates per-volume translation and explanation counts from the local Pali corpus and local published-content database.
5. Updated workflow labels to V2.3.5.3.

## Required source and editorial gates
- Obtain an exact Burmese translation source with documented redistribution rights, or commission a qualified translation.
- Obtain separate explanation sources and distinguish translation from commentary.
- Resolve the exact 45-volume edition crosswalk with independently checked start/end segment IDs, source provenance, rights evidence, and reviewer reference.
- For every paragraph, validate source Pali SHA-256 and record two real, distinct human reviewers, their review reference/date, and rights evidence.
- Import only approved rows. AI-generated drafts, public unreviewed Bilara Myanmar entries, and existing Maṅgala/Dhammapada draft files must remain unapproved until reviewed.

## APK acceptance criteria
- All 45 Pali books remain readable offline.
- Reader shows translation and explanation separately when locally published and otherwise explicitly indicates missing Myanmar content.
- Coverage reports per-book totals, translation count/percentage, explanation count/percentage, and paragraphs containing both.
- APK update must preserve myanmar_publisher_content.db; backup/restore must re-check source hashes.
- A successful Gradle compile alone is not a complete 45-book Myanmar-content release. APK artifact remains gated by native corpus and approved crosswalk requirements.
