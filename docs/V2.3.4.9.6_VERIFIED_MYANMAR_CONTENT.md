## Implemented
1. Reviewed Myanmar import is now wrapped in one explicit SQLite transaction. Any invalid row rolls back both schema/content changes from the import transaction.
2. Import enforces Myanmar Unicode text, translation/explanation content types, two distinct reviewer names, strict ISO review date, source and rights evidence, 64-character Pāli SHA-256 and exact Pāli paragraph hash match.
3. Added `scripts/report_myanmar_content_coverage.py` for approved translation/explanation coverage, both-content coverage and per-volume percentages.
4. CI generates and uploads the Myanmar coverage report, even when the corpus is absent; missing corpus is reported as blocked/zero coverage rather than success.
5. Updated GitHub build workflow and Android version metadata to 2.3.4.9.6 / 39.

## Editorial CSV contract
`corpus/reviewed_myanmar.csv` remains an empty template until genuine reviewed content is supplied.

Required fields:
- segment_id
- content_type (translation or explanation)
- text_my
- source_ref
- rights_evidence
- reviewer_1
- reviewer_2
- review_reference
- reviewed_at (YYYY-MM-DD)
- source_pali_sha256

Each paragraph may have one approved translation and one approved explanation. They are separate records. Reviewer identities must be distinct. AI drafts are not accepted as approved merely because they contain Myanmar text.
