# Myanmar Tipitaka V2.3.4 — Offline Reader Critical Fix

## Scope
1. Preserve the existing 20-screen UI/UX.
2. Make the local SQLite database the reader's source of truth.
3. Verify all 45 books can be opened and their Pāli passages are rendered.
4. Establish a reviewed Myanmar translation and explanation data model.
5. Do not label AI-generated or unreviewed content as approved Myanmar translation.

## Repository baseline discovered
The selected branch `v2.3-myanmar-review-integration` README describes the app as a demo framework and explicitly says it does not contain canonical Tipitaka texts or the exact earlier mockups. Therefore this patch adds the database foundation and acceptance criteria; it does not claim the 45-book text corpus or APK reader bug is already fixed.

## Reader loading contract
- Resolve a stable `book_id`; do not use display title or list position as a database key.
- Query passages by `book_id`, ordered by `sequence_no`.
- Run reads on an IO dispatcher and expose loading, empty, success, and error states.
- Distinguish: book not mapped, no local passages, database open/query failure, and successful empty section.
- Do not require network access for opening, paging, search, bookmarks, or reading history.
- Use a read-only packaged database or a transactional first-run copy; validate schema version and database integrity before swapping files.
- Keep foreign keys enabled and use parameterized SQL.
- Avoid loading an entire large book into memory; page passages in stable sequence ranges.

## Myanmar content rules
- Translation and explanation are separate records linked to the same stable passage ID.
- Reader defaults to Pāli original; approved Myanmar translation and explanation are displayed only when present.
- `DRAFT`, `IN_REVIEW`, and `REJECTED` rows must never be shown with an “အတည်ပြု” label.
- Record translator/author, reviewer, review date, source reference, and version.
- Preserve Pāli diacritics and Myanmar Unicode. Do not normalize away meaningful Pāli characters.
- Maintain attribution and license metadata for each source edition.

## Required QA gates
- Database: `PRAGMA integrity_check;` returns `ok`.
- Database: `PRAGMA foreign_key_check;` returns no rows.
- Catalog: exactly 45 enabled canonical book records before release.
- Every enabled book opens without network access.
- Every book with corpus data displays its first, middle, and last passage in correct order.
- No book may appear “available” when its passage count is zero.
- Reader handles missing translation/explanation without crashing.
- Approved translation and explanation are joined to the correct passage only.
- Test airplane mode, process restart, low-memory reopen, and Samsung Android devices.
- Build a debug APK and install/test it before calling the release verified.
