## Changes in this release
1. Offline corpus audit no longer assumes a hard-coded 425,953 paragraph count. It compares the actual SQLite paragraph count with the generated `build_info.pali_paragraph_count` metadata.
2. The audit checks pinned source commit and approved edition-mapping metadata.
3. The 45-row MCU crosswalk audit now requires every volume to contain a source family, exact first and last segment IDs, reviewer reference and rights evidence; all 45 must be marked VERIFIED.
4. Crosswalk rows with blank evidence remain UNVERIFIED; the validator refuses to guess edition boundaries.
5. GitHub workflow is relabelled V2.3.4.9.5 and uploads QA reports independently of APK release.
6. APK artifact remains conditional on passing corpus and crosswalk gates.
7. Android version metadata updated to 2.3.4.9.5 / 38.

## Validation policy
- Candidate Bilara source families are not treated as proof of MCU printed-volume boundaries.
- Boundaries are inclusive and must be confirmed against a licensed MCU edition.
- The SQLite generator must preserve source order and prevent a source segment from being assigned to two volumes.
- Myanmar translation and explanation are stored separately.
- Each Myanmar row requires distinct reviewers, rights evidence, source reference, review reference/date and matching Pali SHA-256.
- AI drafts are never auto-approved.
- Empty editorial CSV is reported as no content imported, not as completed translation coverage.

## Current known data blockers
- The 45-volume crosswalk contains candidate titles but has no confirmed source prefixes or segment boundaries; all rows remain UNVERIFIED.
- `corpus/reviewed_myanmar.csv` is currently header-only.
- The source acquisition workflow provides an unmapped Pali staging database, not an MCU-mapped reader database.
- Consequently, a fully populated 45-volume MCU SQLite and a content-complete APK cannot yet be truthfully released.
