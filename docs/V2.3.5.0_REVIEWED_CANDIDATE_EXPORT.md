## Myanmar Tipitaka V2.3.5.0 — Reviewer-Checked Candidate Export

Android version: 2.3.5.0 / versionCode 43
Branch: v2.3.4-offline-reader-critical-fix

### Implemented
1. Added a Candidate CSV export action to the native Myanmar Editorial Workbench.
2. Export requires two distinct local Approve decisions recorded in editorial_reviews.
3. Both approvals must match the two reviewer names declared on the submitted draft; names are compared case-insensitively by the SQLite NOCASE key.
4. Export reopens the installed Pali SQLite read-only, resolves the paragraph by volume and ID/segment ID, and calculates SHA-256 from the exact original Pali body.
5. Exports translation and explanation as separate rows using the reviewed importer CSV contract.
6. Uses Android document picker to let the user choose where to save the CSV; no storage permission or hidden file path is assumed.
7. The export remains a candidate only. It does not modify or publish the canonical offline corpus.
8. Updated Android version and CI source gate to 2.3.5.0 / 43.

### Integrity limits
- Local reviewer names are self-entered and are not authenticated accounts or proof of independent scholarly review.
- Candidate CSV still requires publisher-side read-only audit and the existing verified importer before canonical SQLite changes.
- Rights evidence and source reference are required but must be checked by a qualified publisher/editor.
- No translation or explanation text is generated or auto-approved by this version.
- The current candidate exporter is available in the Android editorial screen; remote admin dashboard, authenticated reviewer accounts, signed audit trail and cloud sync are not included.

### QA
CI checks the export implementation exists, runs reviewed importer tests, corpus and crosswalk checks, coverage report and Android debug compilation. APK artifact publication remains gated on the full offline corpus and crosswalk checks.
