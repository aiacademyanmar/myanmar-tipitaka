# Myanmar Tipitaka V2.3 — Translation & Explanation Review Integration

## Objective
Add paragraph-aligned Myanmar translations and explanations to the 45-volume offline Pali reader without presenting AI output or unreviewed material as authoritative.

## Current verified baseline
- The latest successful offline build contains 45 source-mapped volumes and 425,953 Pali paragraphs.
- The current reviewed Myanmar corpus is empty. No per-paragraph Myanmar translation or explanation is considered approved until a review CSV row passes the importer.
- CST passages and any scraped/AI Myanmar text remain source material or unreviewed candidates. They are not automatically treated as approved Burmese translations.

## Import format
The repository file `corpus/reviewed_myanmar.csv` is the required import file. It starts with this exact header:

`segment_id,content_type,text_my,source_ref,rights_evidence,reviewer_1,reviewer_2,review_reference,reviewed_at,source_pali_sha256`

Use one row per paragraph and content type:
- `translation`: faithful Myanmar translation of the Pali paragraph.
- `explanation`: separate explanatory note; do not mix it into the translation.

Required evidence:
1. Exact `segment_id` from the offline `paragraphs` table.
2. Original Pali SHA-256, calculated from the exact UTF-8 `paragraphs.body` text.
3. Source reference and evidence that the Myanmar source may legally be redistributed.
4. Two distinct real reviewers and a review record/reference.
5. Review date in ISO `YYYY-MM-DD`.

The importer rejects missing evidence, duplicate segment/type pairs, unknown segment IDs, invalid dates, identical reviewers, and hashes that do not match the Pali source. Never invent reviewer identities, review dates, source permissions, or approval.

## Suggested editorial sequence
1. Begin with one short, well-defined Sutta collection as a pilot.
2. Obtain rights-cleared Myanmar source material or commission a fresh translation.
3. Have two qualified reviewers independently check meaning, terminology, and paragraph alignment.
4. Record disagreements and adjudication in the review reference.
5. Export only approved rows to the CSV, then run the offline APK workflow.
6. Check `myanmar_review_coverage.json` and test the translation/explanation pop-up on a device.

## Reader behaviour
- Display only rows marked reviewed by the validated import process.
- Keep translation and explanation visibly separate.
- Show the source reference where available.
- If no reviewed content exists for a paragraph, explicitly say that it is not yet available.
- Do not label the whole collection “complete” until coverage evidence supports that claim.
